## Distribution readiness

The workspace implements subscription worker adapters and bounded orchestration, with explicit model/effort, exact project packets, staged proposals, fixed checks and fresh artifact-bound review before separate application. Deterministic tests and real synthetic subprocesses cover failure contracts. Live Codex synthetic tasks on Windows additionally exercised overlapping builders, unchanged tests, fresh review, guarded application and passing final checks. This is a useful shared workspace with documented limits; formal human pilots are optional. Stronger claims about other providers/platforms or OS isolation require their own evidence.

The new regressions cover actual independent-job overlap, dependency ordering, mandatory project/nested rules, cross-client/path refusal, numeric-only usage metadata, subscription-route refusal, fresh stages on resume, attempt limits, stale status/apply rejection, frozen reviewed bytes, preserved concurrent edits and unresolved-cleanup locks. Tests also exercise worker process cancellation and ordinary descendants using synthetic CLIs. Current final counts and artifact hashes belong to the release receipt outside the untouched kit.

Initial implementation used no live generation. A later explicitly authorised Codex credit trial made six actual CLI calls: one failed first attempt, a captured builder response, a baseline reviewer and the successful three-call parallel run. Initial preflight refused inherited API overrides; new minimal-environment processes used ChatGPT subscription authentication without API fallback or active-setting changes. The requested profile was GPT-6.2 Sol/medium builders and GPT-6.2 Astra/high review. Installed CLI output did not echo backend model or effort, so those observations remain unknown. The example profile is recipient-declared, not an evidence-trained selection policy.

The live trial found three integration issues: exact harmless CLI deprecation notices were rejected, two legitimate numeric usage fields were absent from the coordinator allowlist, and the review prompt did not clearly restrict findings to unresolved defects. Narrow fixes preserve refusal of unknown errors, reroutes, tool events and contradictory reviews. The baseline reviewer accepted the code but supplied three positive notes; that run correctly remained blocked and was not silently reclassified. The parallel run after repair reached verified application in about 20 seconds, with no retries or owner intervention within that run. The earlier failures and repair time remain part of the overall trial; this is not a valid single-versus-parallel speed comparison.

The successful parallel run reported 29,162 input tokens and 580 output tokens. The first failed call's usage was not captured, so total trial usage is incomplete. Token counts are not exact subscription-credit charges. Independent inspection reran all six unchanged example tests on the applied copy and confirmed artifact/review hashes and applied bytes matched. This one small fixture does not demonstrate broad model accuracy or seeded-defect detection by a live reviewer.

The release re-review also found a verification cancellation defect: an interrupted check could keep running after its lock disappeared and leave earlier passing evidence reusable. The repair stops/reaps the ordinary process tree, records cancellation with exit code 130 and retains the lock if cleanup is unresolved. Real child/grandchild and unresolved-cleanup regressions protect this behavior. A forcibly terminated wrapper or deliberately detached process remains outside the graceful-cancellation guarantee.

## Follow-up comparison and reviewer challenge

A fresh six-call Codex trial used the final runtime contract with a small synthetic memory-deduplication and cleanup-planning task. One builder plus reviewer completed in 31.12 seconds; two builders plus reviewer completed in 24.30 seconds. Both passed six fixed checks, independent review, guarded apply, the same final checks and seven hidden cases. Single used 18,892 input / 972 output tokens; parallel used 26,823 / 1,160. Both had zero retries or owner intervention during execution. The parallel result was faster and consumed more tokens in this one ordered run; cache/server/order effects and a single sample prevent a general speed or routing conclusion.

A separate live reviewer rejected a deliberately seeded equal-revision bug that passed the six basic checks. Its finding identified the exact comparison error, the seven-case holdout suite exposed it, and guarded application was refused with original files unchanged. This tests one real review judgment, not all defect detection. The second prepared handoff/routing fixture was validated offline only.

All six calls reported usage: 56,011 input and 2,265 output tokens. Exact credit charges and served model/effort were not exposed. Requested profiles remained Sol/medium for builders and Astra/high for review. Existing credits were authorised; no retries, purchase/top-up or API-key fallback occurred. The implementation did not change after the earlier live repairs. Keep simple tasks with one worker and use parallel jobs for separable work; no automatic model policy was promoted from this example.

## Foundation hardening

The recipient-trial loop added interruption-boundary regressions, combined cancellation/resume accounting and a deterministic holdout reviewer that rejects a defect missed by smoke checks. These use synthetic workers; they do not establish an LLM reviewer's judgment. A clean ZIP extraction also exercises offline onboarding with a minimal child environment and Python site packages disabled for its top-level commands, including a path with spaces, preserved templates, stale verification and semantic checkpoint recovery. This is automated technical testing, not independent human usability feedback.

Two actual coordinator defects were reproduced and repaired: losing a completed future before its receipt was recorded, and losing dispatch ownership if submission was interrupted before returning a future. The former now remains drainable; the latter retains the lease conservatively with unknown usage. Independent review rechecked those boundaries. A Windows path-length failure in the private comparison harness was resolved by short temporary roots; recipients are advised to extract to a short path.

Included subscription allowance was exhausted; the owner subsequently authorised available Codex credits. No purchase/top-up action or API-key fallback was performed. Claude generation remains untested. Authentication, included allowance and credit-spending authority are separate checks. The [recipient pilot](RECIPIENT-PILOT.md) records the required metrics without inventing quota savings.

The [isolation pilot](ISOLATION-PILOT.md) prepares synthetic canaries and validates supplied evidence for a restricted local Docker run. It does not launch Docker or contain the ordinary orchestrator. No usable restricted runtime was established on the development host, so actual OS-enforced client isolation remains unobserved. Missing or failing evidence must be refused; fixture tests are not a real container run.

The local foundation now implements curated project memory, restartable sessions with scoped recall, verification coverage checks, bounded integration execution, reviewed activation and read-only health diagnosis. The executable [acceptance suite](FOUNDATION-ACCEPTANCE.md) checks real CLI processes across memory/restart, incorrect application behavior, interrupted handoffs and evaluator failure/staleness scenarios. It uses synthetic data and no providers.

Independent reviewers found and verified repairs for copied cross-project session state, orphan handoff staging after failed writes, partial check coverage causing false-ready health, incomplete review attestations, and a generic Doppler route that could retain child output. Regression tests protect these cases. Updated Skills CLI, ECC, skilled, Basic Memory, Agent Reach and Doppler help/version smoke checks passed through the shared execution route without account access.

Final release evidence is held outside the untouched kit with the packaged artifact: full regression gate, fresh extraction, four offline acceptance workflows, document links, all 171 vendor hashes and private-file exclusions. Receipts are local self-attestations and remain distinct from independent review and live host observations.

## Failures found and addressed

- Agent Search used the Windows default text codec: changed subprocess decoding to UTF-8 with regression coverage.
- Native skilled exceeded the initial archive entry ceiling and Windows path length: bounded extraction was adjusted for the actual release, validated before writing, and uses extended paths. Earlier partial attempts remain local and are excluded from packaging.
- SkillSpector imports hit long dependency filenames in this nested workspace: Python CLI launch now uses extended import paths. Anthropic is constrained to the pinned upstream lockfile version. Windows report-file output is unsupported upstream; stdout capture outside the scan target was used.
- Anthropic skill-creator's description evaluation uses Unix process-pipe select: its guide explicitly requires WSL/Linux/macOS for that helper and lists PyYAML. Bundled source was not silently modified.
