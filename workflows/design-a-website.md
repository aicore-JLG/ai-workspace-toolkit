# Design a useful website

## Define the job
State audience, starting situation, intended action and the information needed to decide. Separate facts from placeholders. Set deliverable and acceptance checks.

## Choose an art direction
Write a visual brief: tone, typography, palette and layout rhythm, with reasons. Inspect existing identity before changing it. Use original or licensed assets. Prefer product demonstrations to decorative claims.

## Compose the page
Explain what it is, who it helps and how to begin. Give every section a purpose. State deliverables, requirements and next steps. Label synthetic examples. Never invent testimonials or savings.

## Build for access
Use semantic headings, native controls, descriptive links, labelled inputs and visible focus. Check contrast, narrow screens, zoom, long text and reduced motion. Keep reading order meaningful without CSS.

## Observe
Follow [browser review](browser-review.md). Test main actions, downloads, errors and keyboard navigation. Inspect desktop/mobile for clipping and overflow, with real copy.

## Hand off
Supply source, run instructions, limits and check evidence. Get a separate reviewer to assess requirements and renders. Publishing needs authority for its destination; local build success is not deployment evidence.
