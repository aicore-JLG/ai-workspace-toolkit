# Plan, build, review

Use this for a substantial task with an observable deliverable. A small text edit may only need an edit and a check.

1. Read the project's brief and current state. Use `roles/planner.md` to settle scope and acceptance checks. Ask only for missing decisions that affect the result.
2. Use `roles/builder.md` to do the authorised work. Keep a short record of changed files and checks. Preserve prior and concurrent work.
3. Give a separate reviewer the acceptance criteria, final deliverable and needed source evidence. Use `roles/reviewer.md`. Do not tell the reviewer what verdict you want or supply the builder's justification as evidence.
4. Resolve concrete findings and recheck affected behaviour. If a fix changes the artefact, the old review does not cover the new version.
5. Save the handoff, including what remains unverified. Sending and release require authorisation for the destination.

These are role prompts, not installed autonomous employees. Use a separate agent if your AI supports it, or a new conversation. If only the same conversation is available, call the result a self-review. Role files do not create tools, provider access or independent execution.

Role paths are relative to the workspace root. When working in a standalone project, copy only the relevant original prompt or refer to it explicitly; do not load unrelated project data.
